产品 · 架构 · 开发者消费指南

mxenv —— 密钥组装层

不是第五个保险库。Infisical / Doppler / macOS 钥匙串 / dotenvx / 本地文件继续持有各自的值， mxenv 只把 profile 选定的来源组合成一次性子进程环境， 并保证 inspect / audit / 编辑器 / 子进程输出全程无密钥值。

Wave A 已闭环 · 0.12.0 已发布（2026-11-07） 三包分层 L0–L3 项目装即完整可用 MIT mxenv:// 契约
① 产品：解决什么问题 ② 开发者怎么消费 ③ 架构设计 ④ 命名与迁移 ⑤ 落地路线
01

产品：解决什么问题

现状的组合 / 加密 / 审计底座是好的；弱在产品体验与形态 —— 五个具体问题，一个核心架构题。

问题 1

没有统一入口，必须启动才能看

看任何密钥状态都要起一次性编辑会话（15 分钟 TTL、随机 token、开浏览器），看完即废；来源散在四五处，没有上帝视角。

问题 2

命名不好，多套名字并存

mx-env 带连字符难敲、品牌不响；morphix-env / mx-env / ~/.mx-env/ / mx-env.config.json 多名并存。决定统一为 mxenv。

问题 3

管理面体验弱

管理上游（provider 登录态、来源编排、profiles）与编辑键值只有 CLI + 一次性编辑器，没有面板级总览、健康检查和连续操作。

问题 4

开源门面缺 icon

现 logo 是通用无限环渐变图：无 mx 识别、无密钥/组合语义，且仅 PNG 无 SVG 源。（Wave C 重做）

问题 5

开源文档不完整

仓库已 PUBLIC、npm 挂 MIT，但缺 LICENSE 文件、SECURITY.md（密钥工具必须有漏洞披露渠道）、CONTRIBUTING 与模板。

核心架构题

「随时可看」vs「短命安全」

随时可看要求常驻服务；常驻进程意味着长驻攻击面，与现有短命会话的刻意安全设计冲突。如何常驻、如何守住「值不出机器」是本次升级的核心设计题。

产品定位一句话： mxenv 是组装层而不是又一个保险库 —— 值的 ownership 永远留在 provider； 真实差异是「多来源组合 + 同名冲突硬报错 + Agent 上下文卫生」，而不是替代你在 Infisical 与 Doppler 之间的选型。
02

开发者怎么消费

三条产品要求 = 三种消费姿势 = 验收口径。核心承诺：项目装即完整可用；全局装只做加法。

姿势 1 · 项目装（默认）

一个 devDep，运行面全齐

装 mxenv（devDep 或 npx）即获得 run / export / inspect / 来源管理 / edit / migrate 全部能力：可定制上游（sources 按项目任选编排 provider 与 profile），全局变量与项目 env.local 可并用。无配置项目默认吃全局库。不需要 daemon、不需要全局 CLI。

姿势 2 · 全局装（增强）

机器级管理面

装 @morphixai/mxenv-cli 叠加管理能力：shell-init 终端 shim（裸敲 pnpm dev 即完成注入）、全局环境变量/密钥管理。项目命令的名称与行为不因全局安装与否而变化。

姿势 3 · CLI 带 GUI

一条命令进入可视化管理

GUI 不独立发包，作为全局 CLI 内置模块分发（沿用 editor-ui 打进 dist 的既有模式）：面板级来源总览、键管理、migrate 入口、审计查看。（Wave B 交付）

60 秒上手

# 与 Agent 一起用（推荐）：装上打包好的 skill，让 agent 读着安全红线干活
npx @morphixai/mxenv@latest skill install --target project   # 写入 .claude/skills/mxenv/，随仓库提交

# 不用 Agent 也能跑
npm install -g @morphixai/mxenv
mxenv run -- pnpm dev      # 组合 profile 并执行（子进程输出自动脱敏）
mxenv inspect              # 只看 key 名 / 来源归属 / 状态 —— 永远没有值
个人机器级默认值放 ~/.mxenv/.env（chmod 600）：每次运行以低优先级并入组合，除非 --no-global。

配置只写接线，不写值

project/mxenv.config.json 
{
  "sources": {
    "team":    { "provider": "infisical", "paths": ["/ai/api"] },
    "doppler": { "provider": "doppler", "project": "morphicai-api", "config": "dev" },
    "local":   { "provider": "local", "files": [".env.local"], "optional": true, "override": true }
  },
  "profiles": { "dev": { "sources": ["team", "doppler", "local"] } },
  "defaultProfile": "dev"
}

组合链：固定的优先级顺序

LAYER 0
inherited env
继承的 process.env
→
LAYER 1
~/.mxenv/.env
全局库（个人默认值，恒在底层）
→
LAYER 2
全局默认 profile
无项目 profile 时生效
→
LAYER 3
项目 sources
含 local env.local / legacy 配置
→
LAYER 4
-f override
显式覆盖文件，最终生效

同名 key 出现在两个来源时默认报错，靠后来源声明 "override": true 才覆盖（防两个环境的同名凭据静默错选）。 项目 / 显式 profile 生效时替代全局默认 profile —— 要叠加全局源，用 profile 的 extends 引入。

五个内置 provider + 插件协议

infisical · doppler · os-keychain(macOS) · dotenvx(加密文件) · local(明文 dotenv，仅开发用)； 任何 PATH 上的 mxenv-provider-<name> 可执行文件即插件 provider（summon 式协议）。provider 登录/引导留在 provider 侧，不进仓库配置。

Agent 协作：上下文零密钥

mxenv run --serve 让值不进任何进程环境：子进程只拿 MXENV_ENDPOINT/MXENV_TOKEN， 经 mxenv fetch <KEY> 逐键按需取值。加上 skill 内置安全红线（禁 env/cat .env*/贴值）， 形成「Agent 全程不碰明文」的工作链。

命令速查（L2 运行面）

命令用途值安全
mxenv run --profile dev -- <cmd>组合环境并执行（唯一注入路径）注入值对子进程输出 [REDACTED]
mxenv run --serve -- <cmd>值不进 env，loopback 按需取值值不进任何进程环境
mxenv inspect / audit tailkey 名 + 来源归属 / 审计事件只出名字，永不出值
mxenv edit一次性可视化编辑器（loopback + 15min TTL）值驻留浏览器会话，逐键回显
mxenv migrate [--to dotenvx|keychain]明文源迁加密存储备份 + 值级等价验证 + 可回滚
mxenv export / render / injecteval 注入 / 模板渲染 / mxenv:// 解析--dry-run 只报名字；输出 0600
mxenv skill install / docAgent Skill 安装 / 项目 key→source 清单模板与生成物 value-free
mxenv-cli shell-init生成 PATH shim（全局管理面）audit 记 via: shim|cli
03

架构设计：L0–L3 严格分层

纪律（用户定调）：上层只依赖下层；凡出现第二个使用方的能力，即下沉到更低层共享。产品差异（命令解析、输出格式、UI）留在上层。

L3管理面 · 产品
mxenv-cli（暂名）
全局密钥/环境变量管理命令 · 内置 GUI（不独立发包）· daemon（127.0.0.1 + token）· launchd · shell-init shim · 审计聚合 / 项目注册视图（不做文件系统扫描：审计 journal 派生 + mxenv link）
▼ 只向下 · L3 ⊥ L2 零互相依赖
L2运行面 · 产品
mxenv（默认名安装包）
run/export/inspect/render/inject/generate · 来源管理命令（定制上游）· migrate · edit（含 editor-ui / clientAssets 生成链）· skill install —— devDep / npx，项目装即完整可用
▼ 通用能力下沉共享
L1能力层 · 共享
mxenv-core 主入口
组合引擎（全局变量 ∪ 项目 env.local）· provider 适配 · 配置加载 · 审计读写 · 值能力 compose/revealSingle 唯一实现（逐键揭示、单值驻留、默认锁定、值不落日志/审计）
▼ 纯契约
L0契约层 · 纯无 IO
mxenv-core/contracts
配置 schema · mxenv:// 引用语法 · 组合 / 审计 / IPC 类型 · redaction 规则 —— 只要类型的消费方（如 Trellis SDK）零 IO import
外部资源（只经 L1 访问）：上游 provider（值 owner，按项目定制编排：Infisical · Doppler · Keychain · dotenvx · local(dev-only)）· ~/.mxenv/ 全局库（加密）· 项目 config / env.local · 审计 journal（无值）。 GUI 不碰文件、不碰值，只说 daemon 的本地 API；外部 SDK（Trellis 等）直接依赖 @morphixai/mxenv-core。（图中短名 mxenv/mxenv-core/mxenv-cli = npm 包 @morphixai/*，目录段 packages/mxenv*；bin/命令名不受 scope 影响。）

三条关键机制

① 产品包零互相依赖

项目态写操作靠 spawn 项目本地 CLI 对齐版本（解析 cwd → node_modules/.bin → PATH），不靠包依赖；解析不到本地 CLI 就明确失败给安装指引，绝不静默以全局版本改写项目数据 —— 消解「项目钉版本 vs 全局滚动」的错位。

② 值安全 = 单一实现 + 窄暴露

值能力唯一实现在 L1，L2/L3/SDK 只是调用方，GUI 永不直连。同 uid 下 daemon 本就能读文件，进程隔离是神话 —— 真实边界是窄暴露（compose / revealSingle）+ 全量审计 + 值不落输出。

③ 项目注册视图不扫描磁盘

「哪些项目在用」两个源：审计 journal 派生（run/edit 时 append-only 记录 → 聚合出项目列表、最近使用、通道）+ mxenv link 显式置顶。单一事实源，不做文件系统扫描。

值安全边界（诚实版）

无值

Agent / 对话 / 审计 / 日志

inspect、audit、编辑器索引、skill 模板全程只出 key 名与状态；值不进对话、不进日志、不进审计字段。

唯一通道

mxenv run

组合注入是进程拿到值的唯一方式；精确注入值从子进程 stdout/stderr 被脱敏（跨 chunk）。--serve 模式下值甚至不进 env，逐键按需取。

边界诚实

拿到值的进程

这是泄露最小化，不是密码学边界：拿到值的进程仍可主动外传。高风险能力应走 provider 代理/经纪（独立安全设计），而非把凭据递进 run。

Wave B 安全模型升级（短命会话 → 常驻但默认锁定）： 面板随时可开，默认锁定态只显示键名/状态；值回显需显式解锁，沿用逐键 reveal + 单值驻留；空闲自动锁；全部操作进审计（via: host）。 红线：值全程不出机器 —— 云侧（如做）只放无值拓扑，值操作一律跳回本地面板。

进展速览（2026-11-07）与三条验收口径达成度：

结论：地基（Wave A）已闭环，产品体验主线（Wave B）尚未开工——原计划能力未全部闭环，剩余 = reveal-single-capability 立项 → Wave B（daemon/面板/gui/global/host）→ Wave C 开源收尾。
验收口径（三条产品要求）： ① 项目装即完整可用 + 可定制上游 + 全局变量 ∪ 项目 env.local； ② 全局 CLI = 增强体验（装全局只做加法）； ③ CLI 带 GUI 能力。任何实现偏离这三条，即视为回退。
