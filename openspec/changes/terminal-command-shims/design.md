# Design

## Context

mx-env 0.8.0 已发布：组合引擎是纯函数（`composeEnvironment`，以 `{...process.env}` 为底逐 source 叠加，map 结构保证 key 唯一），`run` 是唯一注入路径，`serve`/`fetch`/plugin 已就位。本 change 在其上加一层"入口钩子"，不改组合语义。相关约束：npm 全局安装（bin: `mx-env`/`morphix-env`）；审计通道已 value-free；目标平台 macOS/Linux（POSIX sh）。

## Goals / Non-Goals

**Goals:**
- 声明的命令裸敲即注入，人与 agent 无需改变习惯
- shim 层零新增攻击面：不含值、不新增网络/文件写入、可幂等装拆
- 与 `run`/`run --serve` 语义严格一致（shim 只是 `run` 的透明前置）

**Non-Goals:**
- 对 agent 隐藏值（那是 `run --serve` 与远期 proxy 的职责，见 #4）
- fish/PowerShell/CMD（首版仅 POSIX sh 兼容的 bash/zsh）
- shim 与 `--serve` 的组合（要 serve 显式敲 `run --serve`）
- per-command profile 绑定（注入内容永远由执行时 cwd 的配置决定，见决策 4）

## Decisions

### 1. PATH 目录 shim，而非 shell function/alias

shim 是 `~/.mx-env/shims/<cmd>` 的可执行 POSIX 脚本，rc 里将该目录前置到 PATH。备选：shell function（`eval "$(mx-env shell-init)"`）——只对交互 shell 生效，agent/脚本 spawn 的进程吃不到，与"agent 无感"目标冲突；alias 同理且更弱。PATH 方案与 rbenv/mise 同构，对一切经 PATH 解析的执行者统一生效。

### 2. shim 脚本体内引用 `mx-env` 走 PATH 解析，不固化绝对路径

脚本体：`#!/bin/sh` + `MXENV_SHIM=1 exec mx-env run -- <cmd> "$@"`（`<cmd>` 生成时硬编码）。备选：生成时固化 `command -v mx-env` 的绝对路径——nvm/volta 切换 node 版本后 global bin 路径变化会导致 shim 静默指向旧安装。PATH 解析 + `shell-init` 幂等重跑可刷新是更稳的组合；mx-env 自身命令名已被清单校验排除，无自指递归。

### 3. 递归防护：组合开始之前净化基底 PATH + spawn 时双保险

独立评审发现的准 blocker：组合发生在 spawn 之前，provider 加载会同步 spawn 子进程（doppler/plugin 的 `execFileSync`，env 继承当时 PATH）。若清单声明了恰好是 provider CLI 的命令（`doppler`、`dotenvx`，或 `node`——JS 写的 plugin 脚本会调它），shim → run → 组合期 spawn → 又命中 shim → 无限递归。`sources.ts` 的 dotenvx 路径已把 `dirname(process.execPath)` 钉在 PATH 首位（作者已知此风险但未泛化）。

因此剥离**上移**到 `cmdRun` 入口、`resolveComposition` 之前：净化本进程的基底 PATH（filter-all 移除所有解析为 shim 目录的条目；realpath 两侧归一，darwin 大小写不敏感比较），使组合期所有 provider spawn 与最终子进程都拿到无 shim 的 PATH；`runChild` 保留一次剥离作双保险。`--serve` 路径同享（两路都经同一组合与 runChild）。剥离只移除 shim 目录条目，不触碰其余 PATH 项。

### 4. 项目清单参与 shim 生成，但不绑定项目

`shell-init` 的生效清单 = 全局 ∪ 项目（按执行时 cwd 解析配置）。shim 一旦生成是全局 PATH 钩子；在别的目录触发时，`run` 按当时 cwd 的配置组合环境——同一 `pnpm` shim 在不同项目注入不同 profile，这是**特性而非缺陷**。收敛靠 `shell-init` 重跑（移除不再声明的 shim）。文档须写明："shim 的存在 ≠ 清单当前声明；注入内容永远由执行时配置决定"。

### 5. rc 写入用标记块，默认只打印

`shell-init` 默认输出 PATH 行与目标 rc 路径（按 `$SHELL` 推 `~/.zshrc`/`~/.bashrc`）；`--write` 写入 `# >>> mx-env shims >>>` … `# <<< mx-env shims <<<` 标记块（块存在则替换内容，幂等）；`--remove` 删块 + 删本工具生成的 shim 文件（按文件头标记识别）。不触碰块外任何内容与手工文件；发现 shim 目录中名为保留命令的手工残留文件时警告并提示删除（README 同时写明"不要手工往 shim 目录放文件"）。

### 6. 审计维度经 env 标记传递，不进子进程

shim 设 `MXENV_SHIM=1`；`run` 检测到后记 audit `via: "shim"`，并在净化基底时一并剥离该标记（组合期 provider spawn 与最终子进程都看不到它）。**认账声明**：env 标记可被同 uid 伪造（`MXENV_SHIM=1 mx-env run` 即误标），`via` 是观测维度，SHALL NOT 被任何未来的门禁逻辑当作安全断言。备选 hidden CLI flag 会被 `--` 参数透传干扰，不值得；fd 传随机 token 复杂度不值。

### 7. shim 脚本带 `command -v` 守卫

生成的脚本体：

```sh
#!/bin/sh
# mx-env shim — regenerated by `mx-env shell-init`; do not edit by hand.
command -v mx-env >/dev/null 2>&1 || { echo "[mx-env] mx-env not on PATH; reinstall morphix-env or run 'mx-env shell-init --remove' to clean up this shim." >&2; exit 127; }
MXENV_SHIM=1 exec mx-env run -- <cmd> "$@"
```

mx-env 被卸载/nvm 切版本导致 shim 残留时，用户得到可操作的指引而非裸 `command not found`。文件头标记同时用于 `--remove` 与收敛时识别"本工具生成的 shim"。

### 8. `shims` 校验的爆炸半径：组合路径降级、shell-init 硬失败

校验挂进组合路径会让一个 shim 拼写错误炸掉该项目下所有 mx-env 命令——便利层不应成为核心注入路径的单点故障。因此：`shell-init` 对非法条目硬失败；组合路径（run/export/render/generate）发现非法 `shims` 字段时 stderr 警告并忽略该字段，注入照常。

### 9. 保留名清单集中定义 + 大小写规则

常量 `RESERVED_SHIM_NAMES` 集中枚举：全部 CLI 命令名（run/fetch/export/render/inject/generate/gen/inspect/audit/edit/doc/skill/shell-init/help）、bin 名（mx-env/morphix-env）、内部入口（__mx_editor）；新增命令时必须同步（parity 测试固化）。比较与清单内去重均大小写不敏感（macOS 文件系统默认大小写不敏感，`RUN` 会命中 `run` 的 shim 文件）。`/`、`\`、空白一律拒绝（`\` 在 POSIX 文件名合法，但是给未来埋雷）。

### 10. Agent Vault 的 stripEnvKeys 教训在本架构不适用

已核查：Agent Vault 需要 strip 是因为它向 env **追加**键值（POSIX 首个匹配生效）；mx-env 组合是**重建**整个子进程 env map（key 唯一、collision 由 override 规则显式处理），无 first-match 面。此结论由设计论证固化，不单列测试（JS object 无重复 key 的表达形式，测试只能空转）。

## Risks / Trade-offs

- [shim 目录在 PATH 中但被更前面的同名工具抢先（volta 的 pnpm 等）→ shim 静默不生效] → `shell-init` 对每个生效清单命令做 PATH 解析校验：解析结果不是对应 shim 文件路径即 stderr 警告（不阻断）并给出修复指引——这比"PATH 前段"更可测。
- [npm 全局 bin 不在 PATH（nvm 切换、GUI spawn 的 agent 环境 PATH 残缺）→ shim 执行失败] → shim 脚本失败时报错文案指明检查 `command -v mx-env`；文档说明 agent 场景 PATH 要求。
- [项目清单生成的 shim 在项目外目录仍可触发] → 决策 4 的语义声明 + `shell-init` 重跑收敛。
- [Windows 不支持] → README 声明 macOS/Linux；Windows 用户继续显式 `run`。

## Migration Plan

纯新增，无迁移。卸载路径：`mx-env shell-init --remove` + 删除 rc 标记块即完全回退。
